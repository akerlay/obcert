# Cheburcert — дизайн

Дата: 2026-08-27

## Проблема и цель

Корневой сертификат Минцифры РФ (Russian Trusted Root CA) при полном доверии
позволяет государству выпускать валидный TLS-сертификат для **любого** домена, то
есть технически даёт возможность MITM всего HTTPS-трафика. При этом ряд российских
ресурсов (Госуслуги, банки) отдают именно такие сертификаты, и без доверия к корню
Минцифры они не открываются.

Cheburcert решает это компромиссом: доверять корню Минцифры **только для
явно перечисленных пользователем доменов**. Механизм — локальный доверенный CA с
расширением `nameConstraints`, которым кросс-подписывается корень Минцифры.

Целевая аудитория — **обычные люди**, не администраторы. Требование: скачал `.dmg`,
перетащил в Applications, запустил, вписал домены, нажал одну кнопку. Никакого
терминала, `brew`, ручного `sudo`.

Прототип для Linux и объяснение механизма:
- https://lleo.me/dnevnik/2026/08/18
- https://habr.com/ru/articles/1071256/

## Криптографический механизм

Цель — построить цепочку доверия так, чтобы реальный сертификат российского сайта
достраивался до **нашего** ограниченного корня, а не до безусловно доверенного
корня Минцифры.

Компоненты, которые генерирует приложение:

1. **Локальный корневой CA** (`localRoot`):
   - Свежая пара ключей (генерируется на машине пользователя, приватный ключ
     никуда не уходит).
   - Самоподписанный.
   - Расширения: `basicConstraints = critical, CA:TRUE, pathlen:5`;
     `keyUsage = critical, keyCertSign, cRLSign, digitalSignature`;
     `nameConstraints = critical, permitted DNS = <список доменов>,
     excluded IP = 0.0.0.0/0 и ::/0` (запрет выпуска на IP-адреса).
   - Устанавливается как **доверенный корень**.

2. **Кросс-подписанный корень Минцифры** (`crossCert`):
   - `Subject` = Subject реального корня Минцифры.
   - `Subject Key Identifier (SKI)` = SKI реального корня Минцифры.
   - **Публичный ключ** = публичный ключ реального корня Минцифры (эквивалент
     `openssl x509 -force_pubkey` из статьи).
   - `Issuer`/`Authority Key Identifier` = указывают на `localRoot`.
   - Подписан приватным ключом `localRoot`.
   - Дублирует `nameConstraints` (на случай браузеров, применяющих ограничения не
     с самого верха цепочки).

Почему работает: промежуточный сертификат Минцифры содержит AKI, указывающий на
корень Минцифры. Наш `crossCert` имеет тот же Subject/SKI/публичный ключ, поэтому
цепочка `сайт → промежуточный Минцифры → crossCert → localRoot` строится и
проверяется по подписи. `localRoot` доверенный, но его `nameConstraints`
ограничивают допустимые домены. Безусловный оригинальный корень Минцифры в
хранилище **не добавляется**.

3. **Промежуточные сертификаты Минцифры** — устанавливаются как недоверенные
   промежуточные звенья, чтобы цепочка достраивалась, даже если сервер не отдал их
   в handshake.

### Модель домена

Один элемент списка = один суффикс в `permitted DNS`. По правилам name constraints
запись `sberbank.ru` покрывает сам домен и **все** его поддомены (`online.sberbank.ru`
и т.д.) — отдельный wildcard-синтаксис не нужен. Запись вида `.ru` покрывает всю
зону `.ru`. Приложение нормализует ввод (убирает `https://`, `*.`, пробелы,
приводит к нижнему регистру, поддерживает Punycode для `.рф` → `.xn--p1ai`).

## Ограничение платформ (честное предупреждение)

`nameConstraints` строго соблюдаются **только в Firefox** (собственное хранилище
NSS). В Safari и Chrome (системный Keychain / Security.framework) соблюдение
name constraints исторически ненадёжно — сертификат Минцифры может быть принят и
для домена вне списка. UI показывает это явным предупреждением, а не прячет.
Приложение всё равно ставит во все браузеры (пользователь просил «все сразу»), но
не создаёт ложного ощущения полной защиты в Safari/Chrome.

## Технологический стек

- **Язык/UI**: Swift + SwiftUI, нативное `.app`.
- **Крипта**: пакеты Apple `swift-certificates` + `swift-crypto`. Позволяют
  генерировать ключи, собирать X.509 с произвольными расширениями (включая
  `NameConstraints`), задавать произвольный публичный ключ и подписывать чужим
  приватным ключом — то есть реализовать кросс-подпись без внешнего `openssl`
  (системный LibreSSL на macOS не поддерживает `-force_pubkey`).
- **Firefox NSS**: бандлённый бинарник `certutil` (+ необходимые библиотеки NSS/NSPR)
  в `Cheburcert.app/Contents/Resources`, чтобы не требовать `brew install nss`.
- **Распространение**: подписанный и нотаризованный `.dmg`.

## Архитектура (модули)

Каждый модуль — отдельная зона ответственности с узким интерфейсом.

### 1. CertFetcher
- Скачивает корень и промежуточные Минцифры с официального источника
  (`gu-st.ru`, PEM-файлы `russian_trusted_root_ca_pem.crt`,
  `russian_trusted_sub_ca_pem.crt` и актуальные суб-CA).
- Возвращает разобранные сертификаты + вычисленный **SHA-256 отпечаток** корня для
  показа пользователю (сверка вручную).
- Кэширует скачанное в `Application Support`, чтобы не ходить в сеть при каждом
  «Применить».
- Ошибки: нет сети,非2xx, не удалось распарсить PEM.

### 2. CryptoEngine
- Вход: список доменов + сертификаты Минцифры (root + intermediates).
- Выход: `localRoot` (cert + сохранённый приватный ключ), `crossCert`, набор
  промежуточных.
- Приватный ключ `localRoot` хранится в `Application Support` с правами `600`.
  Назначение: повторные «Применить» **без** изменения списка доменов не должны
  трогать уже установленный доверенный корень (тот же ключ → тот же корень →
  идемпотентность, не нужен повторный запрос пароля на переустановку). При
  **изменении** списка доменов корень пересоздаётся с новым ключом, старый
  удаляется из хранилищ, ключ перезаписывается.
- Полностью детерминирован и офлайн → покрывается юнит-тестами.

### 3. TrustStoreInstaller (протокол) с двумя реализациями

**KeychainInstaller**
- Ставит `localRoot` как доверенный корень + `crossCert` и промежуточные (без флага
  доверия) в **System keychain**.
- Требует прав администратора.
- Умеет удалять ранее установленное (идентификация по метке/SKI).

**FirefoxInstaller**
- Находит профили: `~/Library/Application Support/Firefox/Profiles/*` (парсит
  `profiles.ini`, обрабатывает несколько профилей).
- Ставит через бандлённый `certutil`:
  `certutil -d sql:<profile> -A -t "C,," -n "Cheburcert Local Root" -i localRoot.crt`.
- Прав администратора **не** требует (свои файлы пользователя).
- Предупреждает, если Firefox запущен (риск блокировки `cert9.db`); рекомендует
  закрыть. Записывает в закрытую БД.
- Идемпотентно: повторная установка обновляет, а не плодит дубликаты.

### 4. PrivilegeRunner
- Собирает все привилегированные операции Keychain в **один** авторизованный вызов
  (нативный системный диалог пароля администратора) — один запрос пароля на одно
  «Применить».
- Firefox-операции идут в обход, без повышения прав.
- v1: через штатный механизм авторизованного запуска. Возможный апгрейд —
  привилегированный helper через `SMAppService` (в v1 не требуется).

### 5. DomainStore
- Хранит список доменов и выбранные пресеты в
  `~/Library/Application Support/Cheburcert/domains.json`.
- Нормализация и валидация ввода (см. «Модель домена»).
- Пресеты (встроенные наборы): «Госуслуги», «Крупные банки», «Весь .ru / .рф / .su».

### 6. Verifier
- Читает состояние: какой корень установлен, в какие хранилища, актуален ли он
  относительно текущего списка доменов.
- Тест-проверка: локально валидирует, что собранная цепочка проходит проверку для
  примера из списка и **не** проходит для домена вне списка (например `example.com`).
- Питает статусную плашку и кнопку «Проверить».

### 7. UI (SwiftUI)
Одно окно (макет согласован визуально):
- **Сверху**: статусная плашка (включена/выключена, в какие браузеры установлено) +
  «Проверить».
- **Слева**: счётчик доменов, поле добавления, поле поиска по списку,
  прокручиваемый вертикальный список доменов с удалением построчно, кнопки пресетов.
- **Справа**: «Применить» (зелёная, основное действие) и «Удалить всё» (опасное,
  красный контур).
- **Снизу**: жёлтое предупреждение про ненадёжность в Safari/Chrome со ссылкой
  «Подробнее».

## Основные потоки

**Первый запуск / Применить**
1. Пользователь редактирует список доменов (или берёт пресет).
2. «Применить» → CertFetcher (если нет свежего кэша) → показать/сверить отпечаток →
   CryptoEngine собирает `localRoot` + `crossCert` → FirefoxInstaller (без пароля) →
   один запрос пароля администратора → KeychainInstaller → Verifier обновляет статус.

**Смена списка доменов**
- Пересоздать `localRoot`/`crossCert` с новыми `nameConstraints`, удалить прежние из
  хранилищ, установить новые (один цикл, один запрос пароля).

**Удалить всё**
- Удалить `localRoot`, `crossCert`, промежуточные из System keychain (с паролем) и из
  всех профилей Firefox. Кэш и приватный ключ по желанию можно оставить или стереть;
  по умолчанию — стереть установленное, конфиг доменов сохранить.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет сети при скачивании | Сообщение + предложить повтор; если есть валидный кэш — предложить использовать его |
| Отпечаток корня не совпал с ожидаемым/предыдущим | Стоп, предупреждение о возможной подмене, не устанавливать |
| Firefox запущен | Предупредить, предложить закрыть и повторить (или продолжить на свой риск) |
| Нет профилей Firefox | Не ошибка: пропустить Firefox, поставить только в Keychain, отразить в статусе |
| Неверный пароль администратора / отказ | Откатить частичную установку, сообщить, оставить систему в согласованном состоянии |
| Повреждённый/непарсируемый сертификат | Явная ошибка, не устанавливать |
| `certutil` недоступен/сбой в профиле | Сообщить, какой профиль не удался; остальные не откатывать без нужды |

## Тестирование

- **CryptoEngine** — TDD, юнит-тесты: генерация цепочки детерминирована и офлайн;
  проверяем, что итоговая цепочка валидна для домена из списка и отвергается для
  домена вне списка (через локальную проверку X.509 средствами swift-certificates);
  корректность `nameConstraints`, `force_pubkey`-эквивалента, SKI/AKI-связок.
- **DomainStore** — юнит-тесты нормализации/валидации (Punycode, срезание `*.`,
  `https://`, дубликаты, регистр).
- **CertFetcher** — тесты парсинга PEM и вычисления отпечатка на фикстурах (без сети).
- **Installer'ы** — тесты с моками путей/команд (аргументы `certutil`, разбор
  `profiles.ini`); реальная установка проверяется вручную на чистой системе, т.к.
  трогает системные хранилища.

## Вне области v1 (YAGNI)

- Windows/Linux (стек выбран нативный macOS; кроссплатформенность не требовалась).
- Привилегированный helper через `SMAppService` (достаточно одного авторизованного
  вызова).
- Автообновление корня Минцифры по расписанию (скачивание — по действию
  пользователя; фоновое обновление можно добавить позже).
- Импорт/экспорт списка доменов, синхронизация между машинами.
